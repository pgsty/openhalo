# PostgreSQL 19.0 kernel port

OpenHalo 19.0.0 ports OpenHalo to the released PostgreSQL 19.0 kernel.
The starting point includes the existing `aux_mysql 2.0` source cleanup and its
consolidated installation SQL. It is not a published OpenHalo release.
The later [19.0.0 review](REVIEW-19.0.0.md) adds product identification, review
fixes and a new test round. The validation table below describes the initial
port; consult the review report for the subsequent Linux/PGXS/sanitizer coverage.

## Port decisions

- Keep native PG19 startup, direct TLS and delayed cancel handling. Alternative
  protocol sockets still enter the extension's handshake and authentication.
- Expose PG19's `SetSequence()` API for logical sequence synchronization and keep
  OpenHalo's atomic `SetSequenceValueAtLeast()` through the common implementation.
- Keep PG19's fast foreign-key checks for ordinary triggers. MySQL IGNORE preflight
  uses the warning-capable path; self-referencing rows and null-key checks retain
  their existing semantics without closing an unopened relation.
- Serialize `OnConflictExpr.lockStrength` in PG19's native field order. Optional
  OpenHalo flags follow the native fields. PG18 stored trees are converted by
  dump/restore or `pg_upgrade`; PG18 catalog files are not read directly by PG19.
- Forward the new planner `ExplainState` argument; adapt const query-jumble hooks,
  explicit table scan/fetch flags and the fixed-size shared-memory hash API.
- Implement both bounded and NUL-terminated PG19 collation callbacks, preserving
  MySQL GENERAL_CI and PAD SPACE behavior. Use designated method initializers.
- Return a static private index method table: PG19's btree handler returns a
  read-only static table, which must never be modified or allocated per query.
- Use `ErrorSaveContext` with the PG19 numeric APIs; include headers explicitly
  instead of depending on former transitive includes. Avoid local names that
  shadow PG19's new `varlena` typedef.
- Remove obsolete PostgreSQL scanner warning/string-state variables from the
  MySQL scanner. Its own backslash escaping remains intact. Map legacy CLUSTER
  grammar to PG19's `RepackStmt` and use the current subscription enum.

## Build and verification

Build with GNU make. Meson deliberately rejects configuration because it does
not build the complete OpenHalo extension. Always use a fresh build directory
or `--enable-depend`, and install the matching kernel and extension together.

```sh
mkdir /path/to/build19
cd /path/to/build19
/path/to/source/configure --prefix=/path/to/install19 --with-openssl \
  --with-lz4 --with-zstd --enable-debug --enable-cassert --enable-depend
make -j8
make install
printf '%s\n' 'mysql.listener_on = off' > /tmp/openhalo-regression.conf
make check TEMP_CONFIG=/tmp/openhalo-regression.conf
make -C src/test/isolation check TEMP_CONFIG=/tmp/openhalo-regression.conf
```

The 2026-11-20 validation uses native macOS arm64, Clang, OpenSSL and ICU.
Both debug (with assertions) and release builds were installed and tested.
Test instances listen on separate loopback
ports; their schemas and users are disposable. The comparison server is Oracle
MySQL 5.7.44 in a disposable container.

| Validation | Result |
|---|---|
| Debug and release build/installation | Both passed |
| PostgreSQL core regression | 243/243 passed on each build |
| PostgreSQL isolation regression | 139/139 passed on the debug build |
| PG19 port regression | Both builds passed stored-query row locks, cancellation, native direct TLS, MySQL TLS and literal/default round trips |
| MySQL integration | 13 suites passed on each build: PyMySQL, binary prepared statements, DML/FK, binary types, generated columns/policies/export, pending FK, privileges, collations, prefix/btree indexes and transactions |
| Smoke and client drivers | Release build: 26/26 groups, no skips; SQL, AB comparison, prepared packets, RSA/fast/TLS authentication, wrong password, mysqlslap, Go and Connector/J |
| MySQL 5.7 comparisons | All 9 Route A groups passed, including 221 collation names across VARCHAR/CHAR/TEXT with documented approximations; `release_fixes.py` passed 922 assertions |
| Major upgrade | PG18.6 / aux_mysql 2.0 → PG19.0 / aux_mysql 2.0: both debug and release targets passed `pg_upgrade --check`, copy upgrade and post-upgrade data/behavior checks |
| Logical backups | PG19 pg_dump/pg_restore, MySQL 5.7 mysqldump/replay, and unchanged dump restored on MySQL 5.7 passed |

The smoke harness now selects UTF8MB4, keeps stdout and stderr separate, and
omits only MariaDB's failed-statement echo when comparing with Oracle's client.
The original expected SQL results and errors are unchanged. The affected SQL
cases were also compared with the PG18.6 input snapshot. RSA/fast authentication
explicitly disables TLS; Oracle clients request the server public key.

Local evidence is retained outside Git at `/tmp/openhalo-pg19-20261120`:
`check19.log`, `check19-release.log`, `isolation19.log`,
`integration-status.tsv`, `release-tests/integration-status.tsv`,
`smoke19-release-complete/`, `reference-status.tsv`, `release-fixes19.log`,
`pg19-kernel.log`, `pg19-kernel-release.log`, `major-upgrade-verified/`,
`major-upgrade-release/` and `roundtrip19-mysql57.log`.

The upgrade test compares every index/constraint definition while allowing their
DDL declaration order to change. Column order, data, generated expressions,
foreign keys and table options must remain equal. It also checks actual prefix
uniqueness, FK enforcement/cascade and the next AUTO_INCREMENT value.

Run `tests/pg19_kernel.py` with the PG/MySQL environment described in
[TESTING.md](TESTING.md). Run the major upgrade test using separate prefixes:

```sh
python3 tests/pg19_upgrade.py --old-prefix /path/to/openhalo18-aux2 \
  --new-prefix /path/to/openhalo19 --work-dir /tmp/openhalo-major-upgrade
```

## Limits

No 1.x → 2.0 extension update script is provided by the input source cleanup;
this port does not claim that upgrade path. See [MIGRATION.md](MIGRATION.md).
The local MySQL 26.7 mysqldump uses a repeated `SESSION` assignment syntax the
existing MySQL grammar does not accept; use the validated 5.7 client for the
round-trip procedure. Windows, platforms not listed in the review report and
third-party binary extensions require their own build and application validation.
The initial port checked PGXS only with a dry run and did not run `check-world`;
the subsequent 19.0.0 review records actual PGXS and full-suite test executions,
including failed attempts, corrections and remaining limits.
The imported upstream GitHub workflow is opt-in (`PG_CI_ENABLED`) and includes
Meson jobs; it is not an OpenHalo CI acceptance result.
